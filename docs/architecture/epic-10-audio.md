## 1. Outcome

Make actions feel satisfying with sound while keeping the browser experience
respectful and easy to mute:

- one shared, game-scoped `AudioManager` (extended from the Epic 0 shell)
  subscribes to the event bus and maps events to sound keys through validated
  data, so adding or retuning a sound is a data change;
- SFX cover combat (`weapon:fired`, `projectile:hit`, `enemy:killed`,
  `player:damaged`), pickups (`drop:collected`), upgrades (`level:up`,
  `card:chosen`), run endings (`run:won`, `run:lost`), and UI interaction
  (new `ui:navigate` / `ui:confirm` / `ui:back` events);
- a menu music loop and a run music loop play through the same manager;
  ending a run fades the run music under the terminal stinger;
- browser autoplay policy is respected: audio stays silent until the first
  user gesture; one-shots fired while locked are dropped, music is deferred
  and starts on unlock — never a queued burst;
- per-key cooldowns rate-limit spammy events through a pure, tested helper;
- `Settings.muted` / `musicVolume` / `sfxVolume` apply **live** through a new
  `settings:changed` bus event emitted only by `GameContext.updateSettings`;
  the Epic 9 settings panel therefore takes effect immediately in the menu
  and on the next constructed scene — with no save-schema change;
- missing or deleted audio assets never throw, never block boot, and log at
  most once per key in development;
- placeholder WAV assets are generated by a committed, deterministic script so
  the whole pipeline is reviewable end-to-end before final sound design
  (explicitly out of scope) lands.

## 2. Architecture-pass findings and frozen corrections

The live repository was inspected at the baseline above (Phaser 3.90 source
included). Read issue #11 through these corrections:

1. **The Epic 0 shell is scene-scoped and settings are read once.**
   `AudioManager` (`src/systems/audio.ts`) is constructed in
   `GameScene.create` (`GameScene.ts:118–120`) with `setMuted`/`setVolume`
   from the initial snapshot, lives in the scene `systems` array, and its
   `destroy()` calls the **global** `sound.stopAll()`. It has no bus
   subscription, no music, no cooldown, and no unlock flow. MenuScene has no
   audio at all. Epic 10 rescopes the manager to a single game-scoped
   instance (§4); the GameScene construction block is removed.
2. **Phaser's `scene.sound` is the game-global sound manager.**
   `InjectionMap` injects `game.sound` into every scene. Sounds started by
   one scene keep playing after that scene sleeps, and `stopAll()` is global.
   This is why a shared manager works and why scene shutdown must never
   destroy it.
3. **Phaser 3.90 already arms the autoplay unlock.** `WebAudioSoundManager`
   sets `locked = (context.state === 'suspended')` at construction and calls
   its own `unlock()`, which adds `touchstart/touchend/mousedown/mouseup/
   keydown` listeners on `document.body`; the first gesture resumes the
   AudioContext and the manager emits `'unlocked'` on its next update tick.
   Epic 10's `AudioManager.unlock()` is therefore a small guarded delegate
   (§8), not a parallel unlock implementation, and the manager observes the
   `'unlocked'` event to start deferred music.
4. **WebAudio one-shots fired while locked are not queued by Phaser** (unlike
   the HTML5 manager's `lockedActionsQueue`); their buffer sources start
   against a frozen clock and would burst on resume. Frozen policy: SFX
   triggered while locked are **dropped**; only music is deferred (§8).
5. **Issue #11's `AudioMapEntry` is too narrow for run endings.** It is
   extended with `stopMusic` + `musicFadeMs` so `run:won`/`run:lost` fade the
   run loop under the stinger through data, with no special-case code
   (§6). Music *start* stays scene-driven (`playMusic` in `create`); a
   map-driven `musicKey` was considered and rejected because menu entry has
   no triggering bus event and scene ownership is one line, not a subsystem.
6. **Issue #11's `shouldPlay(key, nowMs, cooldownMs)` cannot be pure as
   sketched** — a key-aware stateless function has nowhere to read last-play
   time. Frozen signature: `shouldPlay(lastPlayedMs, nowMs, cooldownMs)` in
   `src/engine/cooldown.ts`; the manager owns the `Map<sfxKey, lastPlayedMs>`
   and a `dtMs`-driven clock (§7).
7. **Cooldown is a property of the sound key, resolved from data.** The issue
   puts `cooldownMs` on each map entry but says `play(sfxKey)` must respect
   it. Frozen resolution: validation guarantees a `sfxKey` appears in at most
   one map entry, so the manager builds an unambiguous
   `sfxKey → cooldownMs` index and `play()` enforces it internally (§6, §8).
8. **Settings must apply live, and Epic 9 deliberately left the seam
   unbuilt.** Epic 9 froze "No `settings:changed` event is added …
   `GameContext.updateSettings` remains the single write boundary" and
   "Epic 10 later owns live music/SFX behavior." Epic 10 adds exactly that
   event, emitted only from `createGameContext.updateSettings` and only when
   the settings object identity actually changes (§5). There is no in-run
   settings UI; menu changes therefore apply before the next `GameScene` is
   constructed, and the shared manager additionally reacts immediately.
9. **UI sounds require new bus events.** Epic 9's menu/pause/summary views
   dispatch commands without any audio seam, and their controllers are
   headless (no bus). Frozen contract: three additive events —
   `ui:navigate`, `ui:confirm`, `ui:back` — emitted **only from view/scene
   dispatch points** listed in §10. Controllers stay headless; the shared
   `ui/modal.ts` helper is not modified.
10. **There are no assets, no `public/`, and no preload anywhere.**
    BootScene runs `loadGameData()` in `create` and loads nothing through
    Phaser. Epic 10 introduces `public/assets/audio/`, a BootScene `preload`
    driven by validated JSON, and a fail-safe convention enforced by
    validation: every asset URL must equal `assets/audio/<key>.wav` (§6, §11).
11. **The initial map extends the issue's list — and `player:damaged` needs
    its cadence solved, not guessed.** The issue's "SFX for … hits" implies
    a player-hit sound, but `player:damaged` has two emission paths with
    very different cadences (`src/entities/Player.ts`): `takeDamage` is
    gated by the 650 ms invulnerability window
    (`RuntimeConfig.gameplay.player.invulnerabilityMs`), while
    `takeEnvironmentalDamage` (hazards, via `HazardSystem`) bypasses
    i-frames and emits **every simulation frame** while the player stands in
    a hazard (~60 emits/sec). Frozen solution: map `player:damaged` with
    `cooldownMs` exactly equal to `invulnerabilityMs` (currently 650). With
    the `>=` boundary this can never mask a legitimate contact hit — that
    path physically cannot emit faster than the cooldown — and it collapses
    the environmental path to the same one-blip-per-i-frame cadence the game
    already presents visually. A data↔config consistency test pins the
    equality so retuning i-frames surfaces the audio value immediately
    (§14). Emitter code is not touched: Epic 10 changes no gameplay rules or
    event payloads, and the single event-level gate covers both paths
    (source-discriminated audio remains a non-goal). Also added beyond the
    issue's list: the three `ui:*` entries. Documented exclusions (§6.3)
    remain unmapped on purpose; mapping them later is a data-only change.

| Owner | Owns in Epic 10 | Does not own |
| --- | --- | --- |
| `src/engine/eventBus.ts` | New event keys; runtime `GAME_EVENT_KEYS` list with compile-time exhaustiveness | Emission or subscription logic |
| `src/engine/cooldown.ts` (new) | Pure `shouldPlay` gate | Key storage, Phaser |
| `src/systems/types.ts` | `AudioSfxAsset`, `AudioMusicAsset`, `AudioAssetCatalog`, `AudioMapEntry`, `AudioData`, `GameData.audio` | Validation logic |
| `src/data/audio-assets.json` (new) | SFX/music key → URL catalog | Event mapping |
| `src/data/audio-map.json` (new) | Event → action map (sfx, cooldown, music stop/fade) | Asset paths, music start |
| `src/systems/validation.ts` | `validateAudioAssets`, `validateAudioMapCatalog`, cross-reference and default assertions | Runtime audio behavior |
| `src/systems/audio.ts` (rewritten) | Full `AudioManager`: subscriptions, guards, cooldowns, music, fades, unlock, live settings | Gameplay rules, settings persistence |
| `src/engine/context.ts` | `settings:changed` emission inside `updateSettings` only | Audio application |
| `src/scenes/BootScene.ts` | `preload` asset load, manager construction/init, registry publication | Audio policy |
| `src/scenes/MenuScene.ts` / `GameScene.ts` | Registry fetch, `playMusic`, `update` forwarding, first-gesture `unlock` wiring, `ui:*` emission at owned dispatch points | Audio internals |
| `src/ui/pause.ts` / `src/ui/runSummary.ts` | `ui:*` emission at existing button callbacks | Map/cooldown rules |
| `scripts/generate-audio-placeholders.mjs` (new) | Deterministic placeholder WAV synthesis | Runtime code |

Explicit non-goals:

- no music composition, final sound design, mixing passes, or audio sprites;
- no dynamic/adaptive combat music (intensity layers, stingers beyond the two
  terminal stingers);
- no new settings fields, no SaveDataV3, no storage-key change
  (`meowcenary.save.v1` untouched), no direct storage access;
- no gameplay-rule, balance, or event-payload changes to existing events;
- no payload-discriminated sounds (e.g. `drop:collected` by `kind`) — the map
  is event-level; that is a later data/model decision;
- no per-sound volume/pitch variation, no positional audio, no pooling of
  sound instances (Epic 12 reconsideration);
- no `reducedMotion` coupling — muting is the only audio accessibility
  control (issue #11 is explicit);
- no new dependencies (Phaser's WebAudio stack only), no DOM audio elements;
- no changes to Epic 9 controller contracts, offer-token flow, banking, or
  scene routing beyond the additive seams in §9–§10.

## 4. Runtime topology and ownership

```mermaid
flowchart LR
  Boot[BootScene] -->|preload: load audio JSON URLs| Loader[Phaser Loader]
  Boot -->|construct + init(bus, settings, ctx.data.audio)| Audio[AudioManager]
  Boot -->|registry.set(AUDIO_MANAGER_REGISTRY_KEY)| Reg[Phaser registry]
  Reg --> Audio
  Menu[MenuScene] -->|fetch; playMusic('music-menu'); update(dt); unlock wiring| Audio
  Game[GameScene] -->|fetch; playMusic('music-run'); update(dt); unlock wiring| Audio
  Bus[EventBus] -->|map events + settings:changed| Audio
  Views[Menu/Pause/Summary views] -->|emit ui:* events| Bus
```

Frozen ownership rules:

1. **Exactly one `AudioManager` per game lifetime.** BootScene constructs it
   after `createGameContext`, calls `init(ctx.bus, ctx.settings,
   ctx.data.audio)` once, and publishes it under
   `AUDIO_MANAGER_REGISTRY_KEY = 'meowcenary.audioManager'` (exported from
   `src/systems/audio.ts`, mirroring `GAME_CONTEXT_REGISTRY_KEY`).
2. **Scenes never construct, init, or destroy the manager.** They fetch it
   with a tolerant `getAudio(): AudioManager | undefined` helper (missing →
   `undefined`, mirroring audio's degrade-gracefully philosophy; scene tests
   stay lightweight). GameScene's current construction block
   (`new AudioManager(this)` + `setMuted`/`setVolume`), its `systems`-array
   entry, and its shutdown `stopAll()` path are removed. The
   `private audioManager?: AudioManager` field is re-added as the fetch
   cache (Slice 2 dropped it with the wiring block; Slice 3 restores it) and
   is cleared — not destroyed — in `handleShutdown`.
3. **The manager is game-scoped but scene-fed for time.** Both interactive
   scenes forward `update(delta)` to it (cooldown clock + fade ramp).
   GameScene forwards next to `controlsView?.update(delta)`; MenuScene gains
   an `update(_time, delta)` that forwards. BootScene never updates it
   (nothing plays during boot).
4. **The manager stays out of every `systems` array.** `systems` entries are
   destroyed on scene shutdown; this manager must survive scene transitions.
   It still `implements System` for shape consistency and testability.
5. **Music is scene-selected, manager-executed.** MenuScene `create` calls
   `playMusic('music-menu')`; GameScene `create` calls
   `playMusic('music-run')`. These two keys are frozen literals; validation
   (`assertAudioDefaults`, §6.2) guarantees they exist in
   `audio-assets.json`. Same-key `playMusic` is a no-op, so scene churn
   (restart, menu revisits) never double-starts a loop.
6. **Run-end music fade is data-driven** through `stopMusic`/`musicFadeMs`
   map entries on `run:won`/`run:lost` — no scene or view special-casing.
   Retry (scene restart → `create` → `playMusic('music-run')`) and Main Menu
   (MenuScene `create` → `playMusic('music-menu')`) restart loops without
   additional logic.

## 5. Event contracts

### 5.1 `GameEventMap` additions (`src/engine/eventBus.ts`)

```ts
import type { Settings } from '../systems/save';   // type-only; precedent: engine/context.ts

interface GameEventMap {
  // … existing 21 events unchanged …
  'settings:changed': { settings: Settings };       // Epic 10; emitted only by GameContext.updateSettings
  'ui:navigate':      Record<string, never>;        // Epic 10; focus/selection movement in a view
  'ui:confirm':       Record<string, never>;        // Epic 10; activation of a UI control
  'ui:back':          Record<string, never>;        // Epic 10; back-out / dismiss / resume navigation
}
```

- The map stays additive; no existing key or payload changes.
  `CHARACTER_PASSIVE_EVENTS` (Epic 6 reactive passives) is untouched.
- `Settings` is imported **type-only**. `src/systems/save.ts` is Phaser-free,
  so `engine/` purity and `gameplay/` importability of the bus are preserved
  (same pattern as `engine/context.ts:9–17`).

### 5.2 Runtime key list with compile-time exhaustiveness

Validation needs the key set at runtime. Add to `eventBus.ts`:

```ts
export const GAME_EVENT_KEYS = [
  'run:start', 'run:paused', 'run:resumed', 'run:won', 'run:lost',
  'player:damaged', 'player:died',
  'enemy:spawned', 'enemy:damaged', 'enemy:killed',
  'weapon:fired', 'projectile:hit',
  'xp:gained', 'level:up', 'card:offered', 'card:chosen', 'weapon:merged',
  'drop:collected', 'currency:changed', 'hazard:triggered',
  'settings:changed', 'ui:navigate', 'ui:confirm', 'ui:back',
] as const satisfies readonly GameEventKey[];

// Compile-time exhaustiveness: fails to compile if a GameEventMap key is
// missing from GAME_EVENT_KEYS.
type _MissingKeys = Exclude<GameEventKey, (typeof GAME_EVENT_KEYS)[number]>;
const _assertExhaustive: _MissingKeys extends never ? true : never = true;
```

`satisfies` rejects array entries that are not real keys; the assertion
rejects a map key missing from the array. Both directions are compile-time
checked; a small runtime test asserts uniqueness and the four new keys.

### 5.3 `settings:changed` emission (only `src/engine/context.ts`)

Inside `createGameContext.updateSettings`, after `current` is reassigned:

- emit `bus.emit('settings:changed', { settings })` **only when the new
  settings object identity differs** from the previous one
  (`applySettingsPatch` already returns the same reference for no-op patches,
  `save.ts:55–65`), so the emission matches `SettingsController`'s `changed`
  semantics exactly;
- emit regardless of `persisted` — a failed write still changes the in-memory
  snapshot (Epic 5/9 semantics), and audio must follow the live snapshot;
- no other call site may emit this event.

## 6. Data contracts

### 6.1 `src/data/audio-assets.json`

```json
{
  "sfx":   [ { "key": "sfx-weapon-fired", "url": "assets/audio/sfx-weapon-fired.wav" } ],
  "music": [ { "key": "music-menu",       "url": "assets/audio/music-menu.wav" } ]
}
```

Types in `src/systems/types.ts`:

```ts
export interface AudioSfxAsset   { readonly key: string; readonly url: string }
export interface AudioMusicAsset { readonly key: string; readonly url: string }
export interface AudioAssetCatalog {
  readonly sfx: readonly AudioSfxAsset[];
  readonly music: readonly AudioMusicAsset[];
}
```

Validation (`validateAudioAssets`, house style: `jsonSafetyErrors` →
`validate` → `throwIfErrors` → assertions):

- record with exactly the fields `sfx`, `music`; both arrays required;
  unknown fields rejected;
- each entry: exactly `key`, `url`; `key` is a content id
  (`isContentId`) prefixed `sfx-` (sfx array) or `music-` (music array);
- **convention enforced:** `url === 'assets/audio/' + key + '.wav'` — one
  format, no path drift, no arbitrary URLs;
- keys unique across both arrays combined;
- caps: ≤ 64 sfx, ≤ 8 music entries;
- `assertAudioDefaults`: music keys `music-menu` and `music-run` must exist
  (scenes reference these literals).

```json
{
  "events": [

    { "event": "enemy:killed",    "sfxKey": "sfx-enemy-killed",    "cooldownMs": 60 },
    { "event": "player:damaged",  "sfxKey": "sfx-player-damaged",  "cooldownMs": 650 },
    { "event": "drop:collected",  "sfxKey": "sfx-drop-collected",  "cooldownMs": 60 },
    { "event": "level:up",        "sfxKey": "sfx-level-up" },
    { "event": "card:chosen",     "sfxKey": "sfx-card-chosen" },
    { "event": "run:won",         "sfxKey": "sfx-run-won",  "stopMusic": true, "musicFadeMs": 600 },
    { "event": "run:lost",        "sfxKey": "sfx-run-lost", "stopMusic": true, "musicFadeMs": 600 },
    { "event": "ui:navigate",     "sfxKey": "sfx-ui-navigate", "cooldownMs": 60 },
    { "event": "ui:confirm",      "sfxKey": "sfx-ui-confirm",  "cooldownMs": 60 },
    { "event": "ui:back",         "sfxKey": "sfx-ui-back",     "cooldownMs": 60 }
  ]

```

Type in `src/systems/types.ts`:

```ts
export interface AudioMapEntry {
  readonly event: GameEventKey;        // imported type-only from engine/eventBus
  readonly sfxKey?: string;
  readonly cooldownMs?: number;
  readonly stopMusic?: boolean;
  readonly musicFadeMs?: number;
}
export interface AudioData {
  readonly assets: AudioAssetCatalog;
  readonly map: readonly AudioMapEntry[];
}
```

`GameData` gains `readonly audio: AudioData`; `loadGameData` /
`validateGameData` wire the two new files exactly like the existing catalogs
(new `ROOT_FIELDS` entry, JSON-name remapping in `rootErrors`, cross-reference
assertions **only** in `validateGameData`, per the knowledge-graph recipe).

Validation (`validateAudioMapCatalog` + `validateGameData` cross-refs):

- root record with exactly `events`; array required; ≤ 64 entries;
- per entry: only the five declared fields; `event` ∈ `GAME_EVENT_KEYS`;
  `cooldownMs` positive integer ≤ 60 000; `musicFadeMs` positive integer
  ≤ 10 000; `stopMusic` literal `true` when present;
- at least one action per entry: `sfxKey` or `stopMusic`;
- `musicFadeMs` requires `stopMusic: true`;
- `event` unique across entries; `sfxKey` unique across entries (§2.7);
- `settings:changed` is **rejected** from the map (the manager owns that
  subscription internally — §8);
- every `sfxKey` must exist in `audio-assets.json` `sfx` (cross-catalog,
  `assertAudioMapReferences`, in `validateGameData` only);
- `player:damaged.cooldownMs` is **not** a free tunable: it must equal
  `RuntimeConfig.gameplay.player.invulnerabilityMs` (§2.11; consistency
  test in §14). All other cooldown values are starting tunables — data,
  adjustable in Epic 11 without code changes.

### 6.3 Deliberately unmapped events

`run:start` (music is scene-driven), `run:paused`/`run:resumed` (pause has UI
sounds), `player:died` (`run:lost` follows immediately), `enemy:spawned`,
`enemy:damaged` (`projectile:hit` covers), `xp:gained` (`drop:collected`
covers), `card:offered` (`level:up` covers), `weapon:merged`,
`currency:changed`, `hazard:triggered` (its damage is already audible
through `player:damaged` at the i-frame cadence — §2.11),
`settings:changed` (manager-owned).
Adding any of these later is a data change plus, at most, an asset row.

## 7. Cooldown primitive (`src/engine/cooldown.ts`, new)

```ts
export function shouldPlay(
  lastPlayedMs: number | undefined,
  nowMs: number,
  cooldownMs: number,
): boolean;
```

Frozen semantics (pure, no Phaser, unit-tested):

- `lastPlayedMs === undefined` → `true` (never played);
- `cooldownMs <= 0` → `true` (no gate);
- non-finite `nowMs` → `false` (defensive; the clock must stay finite);
- non-finite `lastPlayedMs` → `true` (treat as never played);
- otherwise `nowMs - lastPlayedMs >= cooldownMs` (boundary plays).

The manager owns the mutable `Map<string, number>` and a monotonic `nowMs`
advanced only by `update(dtMs)` (finite-guarded: non-finite or negative `dtMs`
adds nothing). This follows the repository time-source rule — no reading
Phaser's clock — and keeps cooldowns deterministic under test.

## 8. `AudioManager` contract (`src/systems/audio.ts`, rewritten)

```ts
export const AUDIO_MANAGER_REGISTRY_KEY = 'meowcenary.audioManager';

export class AudioManager implements System {
  constructor(scene: Phaser.Scene);                 // uses scene.sound (game-global) + scene.cache.audio
  init(bus: EventBus, settings: Settings, audio: AudioData): void;  // exactly once
  play(sfxKey: string): void;
  playMusic(musicKey: string): void;
  stopMusic(fadeMs?: number): void;
  applySettings(settings: Settings): void;
  unlock(): void;
  update(dtMs: number): void;
  destroy(): void;
}
```

Frozen behavior:

1. **init** throws on a second call (double-init is a wiring bug, and tests
   must catch it). It snapshots settings (defensively clamping volumes to
   [0, 1]), builds the `sfxKey → cooldownMs` index, subscribes once per map
   entry, subscribes `settings:changed` → `applySettings`, and subscribes the
   sound manager's `'unlocked'` event. All unsubscribe functions are stored
   and drained in `destroy()` (house pattern: `unsubscribers` array).
2. **play(sfxKey)** guard order (first failure wins, all silent except the
   noted log):
   destroyed/uninitialized → return;
   `!scene.cache.audio.exists(key)` → dev-only `console.warn` **once per
   key** (tracked in a `Set`), return;
   sound manager locked → return (dropped, never queued — §2.4);
   `muted` → return (cooldown is *not* consumed while muted);
   `shouldPlay(lastPlayed.get(key), nowMs, cooldownMsByKey[key] ?? 0)` false
   → return;
   otherwise `scene.sound.play(key, { volume: sfxVolume })` and record
   `lastPlayed.set(key, nowMs)`.
3. **Map-event handling**: only entries that opt in with `stopMusic: true`
   stop the music first (`stopMusic(entry.musicFadeMs ?? 0)`), then
   `play(entry.sfxKey)` — SFX-only entries never touch a playing loop, the
   stinger always dispatches even if the fade logic misbehaves, and test
   order is deterministic.
4. **playMusic(musicKey)**: no-op when destroyed/uninitialized, when the key
   is already the current (or pending) music, or when the asset is missing
   (log once, as in `play`). While locked: store `pendingMusicKey` and
   return. Otherwise stop the current music immediately (an in-progress fade
   is cancelled and that sound is stopped) and start the new loop with
   `scene.sound.add(key)` + `play({ loop: true, volume: musicVolume, mute:
   muted })`, retaining the instance.
5. **unlock flush**: the `'unlocked'` handler marks unlocked and, if a
   `pendingMusicKey` exists, starts it through the normal path (missing asset
   → drop + log once). One-shot SFX are never replayed retroactively.
6. **stopMusic(fadeMs = 0)**: no current music → no-op. Non-finite
   (`NaN`/±Infinity) or non-positive `fadeMs` → stop immediately. Otherwise
   register a fade `{ fromVolume, elapsedMs: 0,
   durationMs: fadeMs }`; `update(dtMs)` ramps `setVolume(from * (1 - t))`
   and stops the sound at `t >= 1`. **No scene tweens** — tweens are
   scene-owned and would strand a game-scoped sound mid-fade on scene
   shutdown; the manual ramp is lifecycle-safe and unit-testable. A repeated
   `stopMusic` during a fade restarts the ramp from the current volume;
   `playMusic` during a fade stops the fading sound immediately.
7. **applySettings(settings)**: clamp + store; if music is current,
   `setMute(muted)` always and `setVolume(musicVolume)` only when no fade is
   running (never fight the ramp); sfx volume applies to subsequent `play`
   calls. Called by `init` and by the `settings:changed` subscription.
8. **unlock()**: guarded delegate — if destroyed/uninitialized, return; read
   `scene.sound`; if it exposes `locked === true` and an `unlock` function,
   call it (Phaser arms its body listeners; its auto-arm at boot usually
   beats us — §2.3). Never resume an AudioContext directly, never add
   DOM listeners here. Safe to call any number of times.
9. **update(dtMs)**: advance `nowMs` (finite/negative-guarded); advance an
   active fade. No other per-frame work.
10. **destroy()**: unsubscribe everything (bus + `'unlocked'`), stop the
    current music immediately, mark destroyed; subsequent calls and all API
    calls no-op. **Never call `sound.stopAll()`** — that is the global
    manager and would kill sounds the manager does not own. Scenes never call
    `destroy()`; it exists for full-game teardown and tests.

## 11. Placeholder assets and loading conventions

- New directory `public/assets/audio/` (Vite serves `public/` at root;
  `vite build` copies it). URLs in data are root-relative
  (`assets/audio/<key>.wav`).
- New committed script `scripts/generate-audio-placeholders.mjs` (Node ≥ 18,
  no dependencies): deterministically synthesizes 8 kHz / 16-bit / mono WAVs —
  short distinct sine/noise blips per SFX key (~120–250 ms) and simple
  loopable tones for `music-menu` / `music-run` (~2–4 s) — writing exactly
  the key set declared in `audio-assets.json`. The implementer runs it once
  and commits the outputs (~14 files, a few KB each); CI never runs it.
- WAV-only keeps decoding universally supported and avoids ogg/m4a fallback
  arrays. Final sound design replaces files in place later — data and code
  do not change.
- Every runtime path tolerates the files being absent (loader continues,
  `cache.audio.exists` gates, log-once). Deleting `public/assets/audio/`
  must produce a silent, error-free game — this is part of the manual
  matrix (§14).

## 12. Lifecycle rules

1. Boot constructs and inits the manager exactly once; `init` twice throws.
2. Scene shutdown clears the scene's field reference and its input listeners;
   it never destroys the manager and never stops global sound.
3. Repeated `Menu ↔ Game` transitions and `scene.restart` must not multiply
   bus subscriptions (one manager, one `init`), input listeners (stored +
   removed), or music instances (same-key no-op; replacement stops previous).
4. A mid-fade scene transition is safe: the fading sound is owned by the
   manager, ramped by whichever scene is forwarding `update`, and stopped at
   completion or by the next `playMusic`.
5. If a scene fails before fetching audio (context missing, render failure),
   audio simply stays where it was — no partial state exists to clean up.
6. `destroy()` is reserved for tests and hypothetical full-game teardown.

## 16. Reviewer traps

  `GameScene.systems` — `handleShutdown` destroys that array.
- Do not call `sound.stopAll()` anywhere; it is global.
- Do not queue or replay one-shot SFX while the sound manager is locked.
- Do not implement fades with scene tweens or `setTimeout`; use the
  `update(dtMs)` ramp.
- Do not emit `settings:changed` from controllers, scenes, or views — only
  `GameContext.updateSettings`, and only on identity change.
- Do not emit `ui:*` from controllers or from the shared `ui/modal.ts`
  helper; only the §10 dispatch points, exactly one event per command.
- Do not read `scene.time.now` or `Date.now()` for cooldowns; the manager
  clock advances only via `update(dtMs)`.
- Do not let `play` consume cooldown while muted, and do not special-case
  `sfxVolume === 0` (volume 0 still dispatches; `muted` is the hard gate).
- Do not retune or remove the `player:damaged` cooldown independently of
  `invulnerabilityMs`, and do not split player-damage audio by source
  (contact vs hazard) — the single i-frame-matched gate is the frozen
  solution for both emission paths (§2.11).
- Do not map `settings:changed` in `audio-map.json` (validation rejects it);
  the manager owns that subscription.
- Do not add `musicKey` to map entries or start music from the map; scenes
  own `playMusic('music-menu' | 'music-run')` only.
- Do not import Phaser (or runtime `systems/` modules) from
  `engine/eventBus.ts` / `engine/cooldown.ts`; the `Settings` import is
  type-only.
- Do not touch save schema, storage key, offer tokens, banking, merge rules,
  or Epic 9 controller APIs; the pause view change is additive (`bus` option)
  only.
- Do not add dependencies, audio sprites, positional audio, per-sound pitch
  variation, or pooling.
