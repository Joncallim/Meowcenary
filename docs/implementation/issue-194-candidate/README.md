# Seeded arenas and tactical interactions: candidate acceptance record

This records the integrated #194 implementation expanded by #233. The integration base is `main` `4f79d6210c3b028b995d67a5cc6e35318b17b2ee`; the original arena candidate source was `8eb50b90affaa06788c25f4d4cc83994fe9e5ebd`. Content revision is `alpha3-2`; generation version remains `1`, the first unpublished version. This is a candidate only: it is not merged or deployed. The independent review disposition is recorded; final exact-head suite/CI results are recorded on the owning issues and PR checks. A named human playtest owner, physical-device checks, and the fun/readability gate remain required before release.

The architecture and implementation contract is in [seeded-arena-layout.md](../../architecture/seeded-arena-layout.md). The generator resolves one immutable layout before resource loading; the same result supplies physics, spawn geometry, hazards, scenery, and resource selection. Layout identity includes content version, arena ID, run seed, and generation version. Arena generation is opt-in and bounded, with authored geometry retained for unprofiled arenas and a validated whole-composition fallback when generation exhausts its budget. No save field or runtime navmesh is introduced. Raised landmarks pair solid collision with their world-art identity and block hostile projectiles; this does not add climbing, jumping, or walkable platforms. Forge's heat grate remains a fixed authored hazard.

The generator preserves two authored landmarks and adds two or three collision-bearing landmarks from each arena's data palette. Placement is bounded to a 32-unit candidate grid, at most 4096 candidates and eight attempts; the connectivity validator uses an 8-unit grid capped at 65,536 cells and the shared player radius plus 8 units of clearance. The final cohort review records all ten layouts succeeding on attempt one. These are correctness and coordinate checks, not human judgments about whether a run feels fun.

## Recorded validation limits

The earlier ordinary full-suite run reports 3103 tests across 209 files passed; separate allocation gates and runner probes/self-audits report 9/9 each. These results are provisional, not an exact-final-head claim. Final full local gates and recorded PR checks/issue comments must establish the tested candidate commit before closeout. The baseline remains main `4f79d621`; arena code is candidate-only. No human played the candidate on a physical phone/controller as part of these records.

The RED/green regressions are retained as compressed full-trace files in `evidence/`: [seven pure-layout failures](evidence/pure-layout-red.log.gz), [four witness/tuple failures](evidence/arena-witness-tuple-red.log.gz), [terminal Training retry](evidence/menuScene-red.log.gz), [three neutral Menu payload failures](evidence/runSummary-red.log.gz), and [reduced-motion warning state](evidence/hazard-motion-red.log.gz). The Training retry now preserves the freshly reseeded request and layout on load retry, then clears them on Back. The three neutral exits pass `{}` to Phaser's Menu start because Phaser can retain an earlier entry payload when a scene starts without new data. That stale `replayRequest` behavior was found during the bounded #201 ledger check; the exact candidate SHA and remediation status are cross-referenced on #201.

The original 47/48 cover-matrix result is retained only as fixture history in [`arena-cover-disposition.json`](evidence/arena-cover-disposition.json). Six RED repeats reproduced a wall-clock/simulation-clock fixture mismatch. The corrected fixture joins real `POST_STEP` frames (up to 40 for cover), moves the shot origin from out-of-world x=−24 to valid x=32, samples the shot synchronously, and verifies it is consumed within 283.333 simulation milliseconds, before its 330-pixel expiry, then reused from the same pool slot. The uncovered positive control still damages the player. Repeated desktop cover/hazard checks passed 4/4; the phone grate warning/active test passed 1/1. See the [six-repeat RED log](evidence/arena-cover-repeat-red.log.gz), [final green log](evidence/arena-cover-final-green.log.gz), [phone green log](evidence/grate-final-phone-green.log.gz), [RED samples](evidence/arena-cover-red-samples.json), and [green samples](evidence/arena-cover-final-samples.json).
